# 桌面工作台状态与接口

工作台使用 Rust、SQLite、Tauri 和 React。业务写入由 Core 应用服务执行，Tauri 负责传输和本机资源授权，React 维护界面会话。

## 状态归属

| 领域 | 模块 | 责任 |
| --- | --- | --- |
| 项目 | `features/project-session` | 唯一可写的 `Project`、摘要分页、打开与切换、读取代次、局部回执更新 |
| 编辑 | `features/editing` | 本地草稿、串行写入、冲突、撤销分组、结构编辑、文稿窗口化 |
| 播放 | `features/playback` | 媒体授权、播放器引用、播放位置和播放状态 |
| AI 与审核 | `features/ai-assistance` | 固定载荷预检、单次授权、交接、审核、任务状态查询 |
| 后台任务 | `features/background-tasks` | 持久化任务摘要、执行代次、重试标识、任务轮询和完成事件 |
| 导出 | `features/export` | 导出偏好、前置检查、确认、导出任务和结果 |

领域模块通过回执、项目 ID 和明确回调协作。后台模块不持有另一份可写项目；编辑模块保存草稿，不把未确认内容写入项目快照。URL 导入的检查、授权和导入动作由 `use-source-import-session.ts` 管理；资源准备由 `use-resource-session.ts` 管理，维护操作使用同目录的 `resource-maintenance.ts`。自动工作流设置和动作由 `use-auto-workflow-session.ts` 管理。项目删除由 `use-project-deletion.ts` 管理；说话人及转写候选审核分别由 `use-speaker-session.ts`、`use-transcription-review-session.ts` 管理。运行环境与模型选择由 `use-runtime-session.ts` 管理，启动与环境刷新由 `use-workbench-startup.ts` 串行协调并先提交草稿；刷新沿用当前项目。资源完成事件由 `use-resource-completion.ts` 处理，转写启动和覆盖确认由 `use-transcription-start-session.ts` 处理，字幕文件预检与导入由 `use-subtitle-import-session.ts` 处理。文稿和历史命令集中在 `transcript-commands.ts`，画布与字幕样式命令集中在 `presentation-commands.ts`。工作台组合这些界面，新增业务状态应放入所属领域。

## 读取与刷新

项目列表通过 `ProjectQuery::List` 读取摘要，每页最多 50 项。摘要不包含字幕、翻译、历史快照、媒体路径或凭据。打开项目才读取工作区内容，历史、质量、节奏和审核任务分别在消费它们的面板打开时查询。工作区查询不读取审核任务、提案和历史列表，也不运行质量或节奏计算；字幕和词时间属于编辑器首屏数据。面板显示加载或失败状态，并提供重试。

普通文字保存采用 `EditReceipt` 更新指定字幕、译文状态和当前版本，保留其他行及任务对象。源字幕涉及词级剪辑时重新读取受影响项目，更新失效的剪辑证据。结构变更仍可重新读取项目，不承诺所有旧操作都只返回增量。各版本化操作返回 `changedDomains`；项目会话统一拒绝与当前项目不符的迟到完整响应。

项目读取带代次。写入确认使旧读取失效，切换项目后丢弃旧项目的界面响应。分页响应在列表被重新加载后失效。读模型标识跟随数据和基线版本保存；普通项目刷新保留已有读模型，按当前面板刷新失效内容。首次打开才查询附属任务域，历史恢复另外刷新受影响的说话人和转写审核数据。

超过 100 段的文稿采用可变高度窗口化渲染。正在输入的字幕行保持挂载，滚动不卸载输入法组合状态；主动定位可以滚动到尚未挂载的字幕。

## 写入与契约

`desktop_api.rs` 是结构化桌面请求的应用入口；文件读取、大小限制和 JSON 解码保留在传输入口。`editing.rs`、`ai_approval.rs`、`transcription/desktop.rs` 和 `project_query.rs` 分别执行领域命令或查询。

`desktop_query.rs` 定义任务、视频导出、模型、资源、说话人和审核预检的读取契约。桌面领域客户端发送结构化请求，Core 直接调用领域服务。浏览器预览的旧命令映射只存在于模拟适配器中，不参与桌面生产调用。

`desktop_control.rs` 定义 36 个资源与任务生命周期动作，包括模型和资源安装、URL 检查与下载、说话人任务、音频分析、Agent 恢复、视频重试、自动工作流启动与控制及任务取消。CLI 对应入口委托同一应用服务；这些动作不应用字幕结果，也不代表所有任务启动都具有统一幂等保证。

`project_commands.rs` 负责桌面项目导入和删除。SQLite 迁移 38 保存操作回执，删除回执不随项目级联删除。导入在获取写锁前检查媒体，在事务内重新检查文件身份；重复提交不创建第二个项目。前端在响应不确定时保留操作标识。删除同时校验确认版本；删除后重复提交返回原回执，不会误删其他项目。

项目编辑包含 `mutationId`、`expectedVersionId` 和操作参数。版本检查、领域修改、快照与幂等回执在同一事务内完成。相同标识重复提交返回原回执，复用标识提交不同内容会被拒绝。无版本的旧 CLI 编辑入口保留兼容性，不提供桌面陈旧编辑检测保证。

桌面结构化请求对 SQLite 和数据库升级互斥锁采用单次最多 2 秒的锁等待；后台任务及旧 CLI 的 SQLite 等待仍为 120 秒。初始化、备份连接也使用对应策略，2 秒不是整个请求的总耗时上限。SQLite `BUSY`、`LOCKED` 及升级锁超时统一返回 `database_busy`，表示可稍后重试。错误不由 Core 推断草稿是否安全：编辑界面依据当前草稿版本的落盘回执，分别显示「本地草稿已落盘」或「当前草稿尚未确认落盘」。用户重试保存沿用原操作标识，不自动新建保存请求。

`src/model.rs` 和各领域 Rust DTO 是 TypeScript 字段契约的来源。`domain_contract.rs` 汇集实际序列化类型，覆盖资源、模型、媒体导入、说话人、转写、审核、AI 服务设置等响应。`platform_contract.rs` 由 Core 与 Tauri 共用，生成运行环境、更新策略和下载事件类型。前端别名仅补充显示状态约束和兼容预览数据；通用 JSON 信封不是运行时业务校验。`ts-rs` 生成 `apps/desktop/src/generated/core-contract.ts`；修改 Rust 类型后先构建 Core，再运行：

```powershell
node tools/generate-core-contract.mjs
node tools/generate-core-contract.mjs --check
```

桌面首次调用检查 Core 能力集合。缺少编辑、AI 授权、后台转写、项目查询、桌面查询、桌面控制、项目生命周期或保存回执能力时显示版本不匹配，不回退到无保护写入。生产领域客户端已不再拼装 CLI 参数。自动工作流启动委托 `desktop_workflow.rs`；字幕、结构化文稿和视频导出使用 `desktop_export.rs` 的版本与回执检查。导出在保存草稿后获取版本，重复请求返回同一回执，视频任务登记和回执提交后才启动执行器。多说话人转写复用转写命令的版本与幂等边界，转写复核走编辑命令。旧 CLI 和旧传输请求仍保留兼容性。

## 回归与验收边界

`architecture.test.ts` 检查实际工作台、唯一项目状态所有者、组件到传输层的依赖和静态运行时循环。串行轮询测试覆盖新增其他任务期间保留既有请求，项目测试覆盖迟到响应、分页重载和返回历史面板。导入测试覆盖重复点击与授权变更后的迟到结果，资源测试覆盖旧配置检查不能覆盖新选择，项目生命周期测试覆盖响应丢失重试、删除版本冲突和迁移失败回滚。

`project_query_tests.rs` 使用 100 个项目、单项目 1 万段字幕，验证分页不会读取完整项目。`large-transcript.spec.ts` 验证窗口化数量、输入法组合期间保留编辑节点及远距离定位。

浏览器与桥接测试不替代 Windows 原生关闭、系统缩放、安装升级、签名或真实设备故障验收。这些检查按 [Windows 候选包验收](windows-candidate-acceptance.md) 单独记录。


### 2026 年 9 月 12 日验证记录

本轮接口迁移与会话拆分完成后，Rust 测试 330 项、CLI 集成测试 25 项、桌面 UI 测试 188 项、E2E 测试 43 项、Tauri 库测试 31 项通过。Rust 保留 1 项原有忽略测试。格式、Clippy、生成契约漂移和桌面构建检查通过，桌面入口产物为 414.71 KiB，低于 550 KiB 限制。

回归发现并修正了启动流程重复释放忙碌状态的问题；并行初始化下的浏览器模拟任务清理和时间轴测试等待也已修正。最终 E2E 为完整套件通过，包含 10000 段字幕窗口化和输入法节点保留、最小窗口布局及任务审核流程。

本次变更通过独立的产物与源码规模检查。完整本地工作区的产物检查仍被原有、未跟踪的 `docs/hackathon` 大媒体文件阻挡；这些文件不属于本次变更。此记录不表示原生设备或候选包验收通过。
